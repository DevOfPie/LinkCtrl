# M61 — The ABI: what an add-on may import, written down and versioned

**Depends on:** [M60](m60.md).
**Discharges:** two of the phase's owed-work items
([phase-4-candidates.md](../phase-4-candidates.md#what-is-still-open)): the
deprecation policy written with the ABI (#2), and the open question *what the
host functions actually are*, which this milestone answers as its central
artifact.

The hardest single artifact of the phase, named as such at planning. *Everything
OIDC needs* is a requirement, not an interface; this milestone turns it into
one. The set of imports **is** the ABI, the host owns it, and add-ons consume a
generated, versioned SDK — the owner's answers of 2026-08-18, all three.

## Done means

- **A host-function set exists, enumerated in one place**, covering what the
  later milestones will expose through it: logging, config reads (scoped to the
  add-on's own keys **and its manifest-declared settings** — M60 declares
  them, M68 edits them, this function is how the module reads the values),
  storage access (scoped by M63's schema boundary), HTTP route handling (M64),
  the session hook (M65), and redirect observation (M66).
  Functions whose backing milestone has not landed are **declared and refused
  at runtime** with a distinguishable error, so the contract is complete on
  paper before it is complete in behaviour — and the refusal is asserted by
  test, not assumed.
- **The ABI carries a version, and the promise is SemVer with deprecation
  windows** (owner-set, against the path-versioning recommendation — recorded
  in [phase-4-candidates.md](../phase-4-candidates.md#the-answers-that-set-its-shape)).
  The manifest's ABI version (parsed since M60) is checked at load: an add-on
  built against a newer major is refused, an older minor within the window
  loads.
- **The deprecation policy is a written document**, `docs/addon-abi.md` or
  beside it, stating: what counts as breaking, the minimum deprecation window,
  and how a deprecation is announced. SemVer without it is a version number and
  a hope — the owed work named at planning, discharged here, not at the close.
- **The SDK is generated from the host's definition** — one authoring point,
  `make generate` alongside sqlc and openapi — into a Go package an add-on
  imports and `GOOS=wasip1` compiles against. The in-repo test modules (M60)
  are rebuilt on top of it, which is the first proof the SDK compiles a
  working consumer.
- **The SDK is consumable from outside this repository**, proven mechanically
  and in-repo: the generated package lives at an importable path with no
  dependency on LinkCtrl internals, asserted by a test that builds a consumer
  against only the SDK package. That property — not anything this loop can
  land in another repository — is what lets `DevOfPie/LinkCtrl-OIDC` compile
  against it from its first commit; the add-on repo actually doing so is
  [M69](m69.md)'s evidence, cited there because this tree cannot mark it
  done.
- **The privacy stance crosses the boundary as an ABI property, not an audit
  of add-on code**: no host function hands an add-on a raw client address —
  what the redirect event (M66) and every other import carry is at most what
  `click_events` may carry, prefix-derived and country-level — asserted by a
  test over the ABI surface, so an add-on cannot store what it is never
  handed. The fifth inherited-rule collision, recorded in
  [phase-4-candidates.md](../phase-4-candidates.md#what-this-collides-with-named-now-rather-than-discovered).
- **Deliberately not done:** the behaviour behind most imports — M63 storage,
  M64 routes, M65 sessions, M66 redirect hooks each land their own limb and
  cite this file. Also not done: any promise of ABI stability beyond 0.x — 1.0
  *means* the contract is stable, and that gate is the close's to state, not
  this milestone's to claim early.

## Risks

- Designing an interface against one consumer (OIDC) risks an ABI shaped like
  OIDC. The named counterweight: the M60 test fixtures and M66's observe-class
  example exercise limbs OIDC never touches, so at least two dissimilar
  consumers compile against the SDK inside this phase.
- The declared-but-refused pattern can rot into permanently-refused if a later
  milestone renames a function. The load-time ABI check plus the enumerated
  set in one file is the mitigation; the mid-phase review (M64.9) reads the
  set against what M62–M64 actually built.
- SemVer judgement calls are exactly the shape that cost nine days of red CI
  (F255's shellcheck argument). The deprecation policy exists to make *is this
  minor or major* a documented test rather than a mood; if it cannot decide a
  real case that arises in this phase, that is a policy defect to fix in this
  phase.
