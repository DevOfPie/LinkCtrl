# M42 — Webhooks

**Depends on:** [M30](m30.md). **Discharges:** the webhooks component of the
Other-surfaces row.

The first outbound HTTP in the product **whose target a user chooses**. The
opt-in reputation feed ([M32](m32.md), `internal/feed/feed.go`) already dials
out, and the container healthcheck does too — but the feed goes to one URL an
*operator* named, and it follows no redirect for exactly that reason. A webhook
target is named by whoever holds the workspace, which is what makes this the
milestone where the SSRF policy applies with full force, **at dial time and not
only at registration**.

## Done means

- Webhook CRUD, with subscription events from a documented, deliberately small
  vocabulary: link lifecycle plus blocked-attempt events.
- Every webhook URL passes `ValidateDestination` with the unappealable tier
  enforced — a metadata-IP target is refused, tested.
- **The delivery client re-validates resolved addresses at connection time and
  follows no redirect to a private address.** A target that passed validation at
  creation can rebind to a private address before delivery; checking only at
  registration is the gap the plan review found in both rival orderings.
- The chosen DNS-rebinding posture for server-initiated fetches is **stated
  explicitly** rather than inherited from the redirect path's accepted gap. The
  redirect path sends a *visitor's browser* somewhere; this sends *the server*,
  and the two do not get the same answer by default.
- Payloads are HMAC-signed with the per-webhook secret; the scheme is documented
  for receivers.
- Delivery rides the existing `webhook_deliveries` table using its pending index,
  claimed via `FOR UPDATE SKIP LOCKED` or a dedicated advisory-lock job (decision
  recorded), with backoff via `next_attempt_at`, abandonment after a documented
  attempt count, per-attempt timeouts, and response codes recorded.
- **Redis stays cache-only** because the queue is Postgres. This dispositions the
  Redis Streams upgrade path: it remains unexercised rather than adopted.
- Deliveries are pruned by age under a documented setting.
- Delivery-outcome metrics stay within the cardinality rules.

## Reopened 2026-08-04 — a batch that holds the job it promised not to hold

Reopened by the owner on [M44.9](m44.9.md)'s triage rather than succeeded, per
[workflow.md](../workflow.md)'s rule, so the correction carries this milestone's
number.

**What is false.** `internal/webhook/webhook.go:69-72` says `DrainBatch` exists so
that *"a backlog drains over several runs instead of holding the job for minutes"*.
It holds the job for minutes at the shipped defaults, with no misconfiguration:
`:213-215` delivers a claimed batch **sequentially**, `DrainBatch` is 20, and
`WEBHOOK_TIMEOUT` defaults to 10s with a dialler that spends the full bound on a
public address that drops SYNs. Twenty times ten is 200 seconds.

The cost does not land on webhooks. `cmd/linkctrl/jobs.go:194-219` is one `select`
in one goroutine and `case <-outbox.C` runs `runMail` and then `runWebhooks`
inline, so for those 200 seconds nothing reads the rollup, dimension, automation
or domain-verification ticks — and Go tickers hold a cap-one channel, so those
ticks are dropped rather than queued. Invitation and verification mail sits in the
outbox, automation stops firing on its advertised clock, and re-verification does
not run. Registration refuses only *private* addresses, so a webhook aimed at a
blackholed **public** one passes validation and is the whole of the setup.
Recorded as [F82](../deferred-findings.md).

Reachable by any signed-in member holding `webhooks.write` — never an API key,
because that scope is non-delegable — and on `LINKCTRL_SIGNUP_MODE=open`, by
anybody who registers.

**What this reopening must not do.**

- **Do not deliver concurrently inside `Drain` without moving the lock.**
  `withLeadership` (`cmd/linkctrl/jobs.go:232-262`) holds its advisory lock on a
  pooled connection released by `defer` when the function returns, so goroutines
  outliving that function deliver **without** the lock D77 exists to hold — which
  is duplicate delivery under split brain, the thing D77 was written for.
- **Do not give webhooks their own ticker and call it fixed.** The stall is the
  shared goroutine, not the shared clock; a second ticker read by the same `select`
  changes nothing.
- Out of scope, and deliberately: [F90](../deferred-findings.md) (the queue's
  instance-wide capacity and its lack of a per-tenant bound) and
  [F91](../deferred-findings.md) (attempts spent without a dial when
  `WEBHOOK_TIMEOUT` is raised). Both are real, both are moderate, and neither was
  approved. Do not fold them in — but do not make either **worse**, and say so in
  the report if the shape you choose touches them.

## Risks

Outbound HTTP is a new capability class for this codebase. Everything that made
`ValidateDestination` necessary applies again, plus rebinding, plus redirects.
