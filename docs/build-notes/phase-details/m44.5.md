# M44.5 — Pre-release adversarial review

**Depends on:** [M21](m21.md)–[M44](m44.md), and [M32.5](m32.5.md) having already
run. **Discharges:** nothing on the scope tables; it is the gate
[M45](m45.md) closes behind.

Phase 1's direct equivalent is the 71-finding review that ran before its PR.

## Why here, as well as at M32.5

[M32.5](m32.5.md) could not see the redirect engine, because it did not exist yet.
This phase's highest-risk work — [M34](m34.md)'s rules on the hot path,
[M35](m35.md)'s durable counter and tripwire amendment, [M36](m36.md)'s variant
attribution, [M40](m40.md)'s verified-domain serving, [M42](m42.md)'s outbound
HTTP — all lands after it. Reviewing the phase once, early, would leave every
dangerous thing unreviewed.

It runs **before** [M45](m45.md) rather than inside it, because findings are work,
work re-triggers validation, and M45's documentation pass has to describe a tree
that is finished. That ordering is workflow.md's, not a preference.

## Done means

- The whole phase is re-read against its claims, M21 through M44, with M32.5's
  findings confirmed as actually fixed rather than assumed.
- Multi-dimension and adversarially verified, exactly as
  [M32.5](m32.5.md) specifies. Only confirmed findings are reported.
- **Beyond code, three things are verified live** rather than by test, because
  Phase 1 learned that reading code against its own intent and *using the product*
  reach different bugs — its M19 exists entirely because someone stood up a fresh
  instance and used it:
  - a fresh instance, set up from scratch, exercising signup / invite / team /
    workspace / org creation end to end;
  - an upgrade from 0.1.0 to this build, confirming migrations are additive, the
    v2 cache key cold-starts without error, and no configuration became silently
    required;
  - the redirect SLO re-measured on the final build, not on an intermediate one.
- Every in-spec finding is fixed; every out-of-spec one lands in
  [deferred-findings.md](../deferred-findings.md) for the owner review that
  [M45](m45.md) then acts on.
- Anything the review changes re-triggers validation from the top, per workflow.md.

## Risks

The temptation at this point is to treat the review as a formality standing
between a finished phase and a release. Phase 1's second review found seven
findings that blocked a tag, on a branch that felt done.
