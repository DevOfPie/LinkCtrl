# M25 — Workspace and organization switcher

**Depends on:** nothing. **Discharges:** groundwork for [M27](m27.md) and
[M28](m28.md). No scope row of its own.

Carved out of the invitations milestone, where it was hidden bulk:
`GetDefaultWorkspaceForUser` is load-bearing in four call sites, and reworking
identity resolution inside a feature milestone would have made both unreviewable.

## Done means

- Identity resolves a deterministic default workspace and organization.
- A switcher exists in UI and API, so a second membership — once [M27](m27.md) can
  create one — is reachable rather than invisible.
- All four `GetDefaultWorkspaceForUser` call sites are converted and tested.
- Behaviour for today's single-membership users is byte-identical. This is the
  claim that matters: every existing instance has exactly one membership per user,
  so the whole milestone must be a no-op for them.

## Risks

The four call sites are the milestone. A missed one silently keeps resolving the
old way and the bug only appears once someone holds two memberships — which is
after [M27](m27.md) ships, in a different milestone's blame radius.
