# M47 — The link page, taken apart

**Depends on:** [M46](m46.md). The edge is hard: this page inherits the shell,
the navigation and the section patterns M46 establishes, and restructuring it
first would mean restructuring it twice.
**Discharges:** the first of the three complaints recorded on 2026-08-06 — the
link configuration page *"leaves a massive mess … difficult to find what you are
looking for in"*.

`pages/link_detail.html` is **805 lines**, more than a fifth of every template in
this product put together, and its backing handler `loadLinkDetail` is roughly 220 more
(`internal/httpx/web_links.go:513`). It carries eight top-level sections in an
order nobody chose: analytics first, then a 186-line edit form, then signed
links, QR, routing rules, the split test, a danger zone, and recent activity.

**The blind tasks measured what that costs.** Changing where a link points — the
most ordinary thing anybody does to a link — took ~35 seconds, and the owner's
note was *"scrolling, which is worse when not looking for the massive QR code"*.
Four of the seven round-one tasks named scrolling as the worst part. This
milestone is that measurement acted on.

## Done means

### The page leads with what somebody came to do

- The destination and the alias are reachable **without scrolling** at a
  1280×800 viewport, asserted by a test that renders the page and checks the
  edit control's position rather than by looking at it.
- Analytics stop being the first thing on a configuration page. Where they go —
  below, behind a tab, on their own route — is the milestone's to decide and to
  record; that they no longer sit between the reader and the edit form is not.
- The eight sections are re-ordered by **how often somebody needs them**, and
  the ordering is written down with what it was derived from, so a later
  reader can disagree with the evidence rather than with a preference.

### The monolith becomes composable, and a test keeps it that way

- The page is decomposed into named partials under
  `internal/ui/templates/partials/`, in the convention the tree already uses —
  `links_table`, `breakdown`, `series_chart` and `worldmap` are all already
  separate files invoked with the `dict` helper.
- **A template scan asserts the decomposition holds**, in the idiom
  [M24.5](m24.5.md) established when it made raw palette utilities fail the
  build: `pages/link_detail.html` may not exceed a stated line count, and a
  section added later goes in a partial or breaks the build. The number is
  chosen when the decomposition is done and is recorded with its reasoning —
  enforcement is a mechanism here, not review vigilance.
- `loadLinkDetail`'s ~220 lines are split along the same seams. A partial whose
  data is assembled by a quarter of a 250-line function is not decomposed, it is
  relocated.

### Behaviour does not change, and that is the falsifiable claim

This is a restructure. The strongest way to say so is a test result rather than
an intention:

- **Every existing integration test touching the link page passes unmodified.**
  Form field names, routes, redirect targets and flash behaviour are unchanged.
- The OpenAPI document is untouched, and the contract test passes without
  regeneration.
- If a test does need changing, that is a behaviour change, and it is either
  reverted or it is called out and justified in the commit. There is no third
  option where a test is quietly adjusted to match a new page.

### The one label that changes, because the tasks proved it does not work

`max_clicks` renders as *Click limit (empty = none)*
(`pages/link_detail.html:211`), with `{{.Link.ClicksConsumed}} used so far.`
immediately below it at `:217`. In the blind task the owner set a limit and then
wrote: *"Unsure if done properly as nothing notes whether the field is setting
for additional clicks or total clicks. Current clicks was 416, was setting the
field to 50 or 466 correct?"*

The answer is 466 — `MaxClicks` is an absolute limit, and `withBudget`
(`internal/link/gates.go:167`) fills the consumed count beside it. **Both facts
were already on the page, adjacent, and still did not compose.** So:

- The control states the total it is setting and what has already been spent
  against it, in one sentence rather than in two elements a reader has to
  relate.
- A test asserts the rendered text names both numbers. The gate's behaviour is
  **not** changed — `MaxClicks` stays absolute, because changing it would
  silently redefine every limit already set.

### Deliberately not done

- **No new component framework, no client-side rendering.** `ui` stays
  stdlib-only, no Node, no CDN, CSP unchanged — the inherited rule, restated
  only because a page this size invites the argument that it needs one.
- **No behaviour, no new capability.** The QR panel's rework is
  [M48](m48.md); the QR settings vocabulary is [M49](m49.md); everything else on
  this page keeps doing exactly what it does.
- **No dark-mode exception.** New markup uses the theme tokens and M24.5's
  template scan applies unchanged.

### Demo

Nothing new to seed — this page already shows every feature the demo has. The
`demoCoverage()` table is unchanged, which is stated rather than left blank so
the omission reads as considered.

## Risks

**Moderate, and concentrated in the diff's size rather than its difficulty.** An
803-line template and a 250-line handler being taken apart in one milestone is
the largest single-file change of the phase, and the failure mode is a section
that renders in the wrong state — a form that no longer round-trips a value, a
permission gate that stops wrapping what it wrapped. The unmodified-tests claim
is the defence, and it is only a defence to the extent the existing tests cover
the page; where they do not, this milestone finds out.

The genuine unknown is the line-count cap. Set too high it enforces nothing; set
too low it forces partials that exist only to satisfy a number. It is chosen
from the decomposition rather than before it, and if it cannot be set at a value
that means something, that is worth saying instead of picking one that reads
well.

Second: re-ordering by frequency is an assertion about how people use the page,
derived from seven blind tasks run by one person. That is far better than
nothing and much less than data. [M51.9](m51.9.md) re-runs those tasks against
the built tree, which is the check on this.

# Reopened — 2026-08-11

**The milestone above shipped and its discharge was false.** It reordered nine
sections and left the page a nine-section vertical stack; ordering is a
permutation, so it decided *which* section is expensive to reach and never *how
many* are. The owner's verdict, on sight: *all the change did was re-order the
problem not solve it.* [F205](../deferred-findings.md) records it. Work below
carries M47's own number, because a reopening keeps the milestone's number.

**Reviewed by [M57.9](m57.9.md), which reopens with this.** [M51.9](m51.9.md)
does not — its range M46–M51 is wholly inside M57.9's M46–M57, so re-running the
later review covers everything the earlier one claimed. Owner-set 2026-08-11.

**Depends on [M46.5](m46.5.md)**, hard: the viewport claims below are browser
claims, and M46.5 is what makes a browser drivable and its result keepable.
*(The glyph claims moved to [M47.5](m47.5.md) with the split.)*

## Done means, as reopened

### The stack becomes tabs

- The link page renders **one section panel at a time**, selected by a tab strip,
  instead of rendering all of them into one column. **There are eight section
  partials** — edit, qr, rules, split, signed, analytics, activity, danger
  (`link_detail.html:48-55`) — plus the inline identity header at `:27-42`, which
  is the page rather than a section and does not become a tab. All eight survive;
  what changes is the shell that arranges them. *(F205 and an earlier draft of
  this bullet both said nine. The page's own list at `:5` counts the header,
  which is not a partial.)*
- **Seven tabs**, owner-set 2026-08-11: Edit, QR, Routing, Split, Signed,
  Analytics and Danger. `link_activity` **folds into Analytics** — it is the same
  data one row at a time, so one tab holds the rollup and the rows. Danger keeps
  its own tab. Eight of the page's sections become seven tabs; the inline identity
  header at `link_detail.html:27-42` is the page and becomes none.
- The strip **scrolls horizontally** rather than wrapping. This is the property
  that made tabs worth choosing over the alternatives — it behaves identically at
  360px and at full width — and it is asserted, not assumed.
- Switching a tab is an **htmx swap**, in the pattern the workspace switcher uses
  (`nav.html:130` at `55dbbc8` — the bullet cited `:88`, and M46.6's restyle
  moved the select without changing its mechanics). **M48's panels are not a
  precedent for this** — `panel.html:26-30`
  says htmx *"is not used here"*; they are the Popover API. The `next` field is
  M48's and is real (`link_qr.html:136,156,226,325,337`); the swap mechanism is
  the switcher's.
- **M48's panel return path keeps working.** Its panels are addressable pages
  carrying a `next` field; one URL serving several tab views has nothing to
  distinguish, so either tabs take a query parameter or the return path is
  re-derived. Whichever is chosen is stated, and a test drives a refusal from a
  panel back to the tab it was opened from.

### The badges are M47.5's, and the strip ships without them

- This milestone is **the layout**; [M47.5](m47.5.md) is **the state feedback**.
  That is the seam the design itself was drawn along — tabs from one option, badges
  from another — and splitting there means neither half is judged against the
  other's bullets.
- The strip therefore ships **bare**, and that is a deliberate intermediate state
  rather than an oversight: a tab strip with no badges is exactly the option that
  was drawn, considered, and found insufficient on its own. It is shippable and it
  is not the finished design.

### The four shipped gates this strip runs into

Every one is enforced today and none was named in the first draft of this plan.
A reviewer found them; they are here so the build does not.

- **`linkDetailLineCap = 60`** (`internal/ui/link_detail_test.go:41`) and the page
  is **57 lines**. Three lines of headroom for a tab strip. The test says raising
  it *"is a decision about the page's structure and belongs in decisions.md, not
  in this constant"* — so the strip is a partial invoked from the page, or the cap
  moves and the decision is written. **Owner-answered; see decisions.md.**
- **The first two form controls must be `url` then `alias`**
  (`link_detail_test.go:207-216`, matching `<(input|select|textarea|button)`). A
  `<select>`-based strip above the edit form fails it. The strip is therefore
  links or buttons whose markup does not match that pattern before `id="url"`, or
  the assertion is amended with its reason.
- **`unboundedHeight` refuses `<ul>`/`<ol>` before `id="url"`**
  (`link_detail_test.go:86-88,224-232`). The strip is not marked up as a list.
- **`linkDetailPrefixPixelBudget = 160`** (`link_detail_test.go:154`) and the QR
  thumbnail already spends 96, leaving **64**. Every inline `<svg>` before
  `id="url"` is summed and must carry a fixed-length `h-` utility — arbitrary
  values like `h-[9px]` are refused (`:103-105`). The glyph size therefore has to
  land on a real utility: `h-2.5` (10px) or `h-3` (12px), not 9 or 11.
- **`linkDetailPrefixBudget = 400` characters**, 93 drawn today (`:159-160`), and
  seven tab labels plus badges go into it.

### The claim is measured, which is what the first attempt did not do

- **The blind task is re-run and the seconds recorded.** M47 cited ~35 seconds to
  change a destination and four of seven round-one tasks naming scrolling, then
  shipped its discharge without ever re-taking the measurement. A number, or the
  milestone repeats its own failure.
- **A kept Playwright spec**, built on M46.5, asserts what no template scan can:
  the strip does not wrap at 360px. Sabotage-verified. *(The glyph-size half of
  this assertion moved to [M47.5](m47.5.md) with the glyphs themselves.)*

### Behaviour does not change, and that is the falsifiable claim

- **Every existing integration test touching the link page passes unmodified**,
  as the shipped half required of the reorder. A strip is navigation; no
  section's behaviour, permission gate or form action changes.
- The four gates above pass **without being weakened**, or each weakening is
  named with its reason in decisions.md. A gate quietly relaxed to fit a redesign
  is the failure `linkDetailLineCap`'s own message is written against.

### Demo

- **Nothing new to seed.** The tabs rearrange sections the demo already shows,
  and every badge reads state the demo already has. `demoCoverage()` gains no
  row. Stated rather than omitted, so the position reads as considered — the same
  reason the shipped half stated its own.

### F206 is not here

- The htmx CSP fix moved to [M46.5](m46.5.md). The owner approved it into this
  milestone; the plan review then found M46.5 runs first and names a clean
  console as one of the two things its kept spec may assert, so leaving the fix
  here would have denied that assertion to the milestone that needs it. The fix
  moved, the decision did not.

## Deliberately not done, as reopened

- **No section is deleted or merged.** All eight section partials and the
  identity header survive; only their arrangement changes. Deciding a section is
  unnecessary is a separate conversation.
- **No sub-routes.** Option D was drawn and not chosen; a link does not become a
  small site.
- **No summary tab.** Option A3 was drawn and not chosen — the landing view stays
  the edit form, because editing is the common task.
- **[F204](../deferred-findings.md) is not fixed here.** The workspace switcher is
  a different screen and unreviewed.

## Risks, as reopened

**A shell rewrite and a kept browser spec are still a real milestone**, and the
honest possibility is that it turns out to be two — which W40 now permits
without a phase-boundary conversation. The badge vocabulary, the glyphs and the
icon home were this file's risk until the split; they are [M47.5](m47.5.md)'s
now, named in its own file.

**A tab strip hides state that a stack showed.** The badges are the mitigation
and they are only as good as the six values behind them *(five, since M47.5's
2026-08-11 reopening removed the Edit count — F211)*; a badge that lies is
worse than a section that is far down the page. Between this milestone and
M47.5 the strip ships bare — the deliberate intermediate state named above.
