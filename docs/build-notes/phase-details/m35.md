# M35 — Gated links: password, signed, one-time, max-click

**Depends on:** [M34](m34.md) — **an ordering choice, not a hard dependency.** The
snapshot already carries `HasPassword`, `MaxClicks` and `OneTime` (snapshot.go),
so these need no bump of their own; riding M34's single v2 bump avoids a second
cold cache. Stated plainly rather than dressed as a technical requirement.

**Discharges:** Security scope row *Password links, one-time links, max-click
links, signed URLs*.

## Done means

- The 422 `not_implemented` stubs are gone. `password`, `one_time` and
  `max_clicks` are settable via API and UI, and the contract test that asserted
  those 422s is updated — sabotage-verified.
- **Password links.** The redirect tree serves an embedded, template-engine-free
  challenge page and accepts a POST for verification. The tripwire tests are
  deliberately amended to allow exactly that one POST route and nothing else; the
  amendment is recorded, restored by counter-edit discipline, and needs owner
  sign-off before it lands. argon2id verification runs only on the submit path and
  reads the hash from Postgres — **the cached snapshot carries only `HasPassword`,
  never the hash**, asserted by test.
- **Signed URLs.** Per-workspace signing secret in additive storage, HMAC
  verification on the hot path, expiring signatures, documented format.
- **One-time and max-click.** A durable Postgres counter consumed transactionally —
  **built here, once; [M36](m36.md) reuses it.** Redis is cache-only and cannot
  count, which is why this is Postgres. Engaged only for links whose snapshot flags
  require it; exceeded serves 410; correct with Redis disabled entirely, tested,
  including a real-concurrency race test on the one-time counter.
- `links.click_count` stays untouched and approximate.
- SLO re-verified: **ungated** links stay under 20ms cached p99. Gated-path latency
  is measured and documented separately in [slo.md](../../slo.md) — the extra write
  is paid only by links that asked for it.

## Reopened 2026-08-04 — three claims about gates, and one status code

M35 shipped four gates and four of its claims turned out false. Reopened by the
owner on [M44.9](m44.9.md)'s triage rather than succeeded, per
[workflow.md](../workflow.md)'s rule, so the corrections carry this milestone's
number. Four rows, one milestone.

### F78 — `HEAD` does not merely avoid spending a click, it skips the check

The bullet above says **exceeded serves 410**, with no method carve-out.
`internal/httpx/redirect_gates.go:229-235` reads
`if !gated || r.Method == http.MethodHead { return gatePassed }`, and `gatePassed`
is `answered:false`, so the request falls through to the ordinary redirect write.
Reproduced live: a `one_time` link answered 302 to the first GET, 410 to the
second, and then **302 with the destination in `Location` to three successive
`HEAD` requests**. `record()` skips HEAD as well, so the disclosure leaves no click
row behind.

`docs/SECURITY.md`'s *"HEAD never spends a click"* is **satisfied** and is not what
is false — D53 bought non-consumption and the code delivered non-checking, which is
strictly more. Recorded as [F78](../deferred-findings.md).

### F79 — the signature is verified against the wrong domain

`internal/gate/signature.go:42-45`, `docs/SECURITY.md:64` and this milestone's
decisions entry all say the domain id is in the MAC so *"a signature minted for one
hostname does not verify on another"*, and the entry calls the case *"not
hypothetical"*, naming M40 as the milestone that creates it. But
`internal/httpx/redirect_gates.go:125` passes `h.DomainID` — the instance default
resolved once at boot — while `internal/link/gates.go:132` signs with the link's
own `row.DomainID`. `redirect.go:176-179` computes the request's real domain into a
local that `passGates` never receives.

Two consequences. A signed link on a verified custom hostname **never verifies**,
so the feature is wholly non-functional there. And a signature minted for alias `X`
on the default domain **does** verify against a different link with alias `X` on a
custom host in the same workspace. Recorded as [F79](../deferred-findings.md).

The same boot constant keys the per-alias password bucket at `redirect_gates.go:211`,
whose comment claims *"the same alias on two domains is two links"*. That limb fails
safe — a shared bucket admits fewer guesses, not more — but it is the same defect
and is fixed here rather than left to look correct.

### F80 — the signed URL is built on the wrong host

`internal/link/gates.go:139` builds `s.baseURL + "/" + row.Alias + …` under a
comment claiming it is *"built from the same base URL the short link is published
under"*. `internal/link/service.go:1225-1230` already holds the domain-aware
helper, called everywhere else and skipped here. Alias uniqueness is
`(domain_id, alias)`, and the default domain is shared across workspaces, so the
returned URL does not merely 404 — where that alias exists on the default domain it
**resolves a different workspace's link**. Recorded as
[F80](../deferred-findings.md).

### F81 — a supported status turns the password into a payload

`internal/httpx/redirect.go:405` answers a successful password POST with
`h.status()`, fed from `REDIRECT_DEFAULT_STATUS`. `internal/config/config.go:776-785`
permits **307** and `docs/configuration.md:174` advertises it. RFC 9110 §15.4.8
forbids a user agent changing the method on a 307, and
`internal/httpx/static/password.html:45-46` is a `<form method="post">` with no
`action`, so the browser re-POSTs `password=<secret>` to the link's third-party
destination. Recorded as [F81](../deferred-findings.md).

### What this reopening must not do

- **F78: do not make `HEAD` consume.** That destroys the feature and is the outcome
  D53 names as unacceptable — a link checker would burn a one-time link's single
  click. `gate.Service.Budget` (`internal/gate/gate.go:205`) is an existing
  **non-consuming** read. It must not become a per-request query for links that are
  not exhausted.
- **F79: no signature that works today stops working.** *(Amended 2026-08-04 at
  step 3.4 — this bullet stood as "the fix invalidates every signature already
  minted". `internal/link/gates.go:132` has always signed with the link's own
  `row.DomainID`, so only the verifier was wrong: a default-domain link has
  `row.DomainID == h.DomainID` and verified correctly before and after, and a
  custom-domain link never verified at all. See decisions.md.)* Patching
  `signatureGate` alone still leaves the password bucket on the stale value with no
  test to catch it.
- **F80: `shortURL` falls back to `s.baseURL` when its hostname lookup returns
  empty.** At this call site that fallback is the bug again. An empty result has to
  be an error here, not a default.
- **F81: answer 303, unconditionally.** It is the one status that mandates a GET.
  303 is **not** in `config.go:776`'s allowed set, so the validator and
  `docs/configuration.md:174` need the same edit — and D53 is written as *"answers
  the **302** itself"*, so it must be **amended**, not silently contradicted.
- **This touches the redirect path**, so the inherited rule applies: re-run the
  [docs/slo.md](../../slo.md) k6 measurement on the **built image** and record it.
  Cached p99 stays under 20ms.
- Out of scope, and deliberately: [F115](../deferred-findings.md), the per-alias
  password limiter's availability cost. D54 chose that keying and only the missing
  risk note survived verification. Do not fold it in.

## Risks

Amending the no-POST tripwire is the riskiest test change of the phase. The
one-time counter under concurrent clicks is the riskiest code: it must be tested
with real concurrency, not a sequential loop.
